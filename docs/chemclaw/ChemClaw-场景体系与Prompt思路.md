## 0. 分类方法

### 0.1 分类主轴

#### 0.1.1 最终采用的 L1 骨架

* ChemClaw
  * **1. 内贸交易与经营**（P0 基本盘）
  * **2. 外贸交易与经营**（P1）
  * **3. 产业研究与决策支持**（P2）
  * **4. 期现与风险管理**（P3，系统补齐）

#### 0.1.2 为什么这样分类

* 候选 A「交易与经营 → 内贸/外贸」把研究、期现挤到二级，导航会把最高频的内贸销售/采购埋深
* 候选 B「按获客/采购/履约/风控横切」更贴近岗位，但会把内贸外贸强行合并，数据与合规差异巨大，MECE 差
* **采用方案**：按**业务世界**分 L1（用户打开产品时先选“我在做国内生意 / 进出口 / 研究 / 期现风控”），再按**业务目标**分 L2，再按**任务簇**分 L3，最后到可点开的 L4
* 企业尽调、价格研判、运费估算等**跨场景能力**不升为 L1，下沉到「共享能力层」与标签

#### 0.1.3 明确拒绝的一级分类

* 企业数据库 / 价格数据库 / 招投标库 / 海关库 / 产业链库
* MCP / Search / Workflow / Skill / Agent
* 电商平台运营 / SEO / 独立站（`[会议明确]` 第一阶段降级，不进 L1）

### 0.2 层级定义

* **L0**：ChemClaw 产品本身
* **L1 业务域**：用户处于哪个业务世界（约 4 个）
* **L2 业务目标**：现在最想完成什么（找客户 / 找货 / 促成交易 / 控风险 / 做判断…）
* **L3 任务簇**：为达成目标的一组相对独立任务
* **L4 可使用场景**：用户可点开场景卡片完成一件明确事情；可自然形成 Prompt
* **L5 原子步骤**：默认不是首页场景，而是 Workflow/Skill/Tool 组件

### 0.3 横向标签（不进主树）

* **角色**：销售 / 采购 / 外贸业务 / 研究员 / 风控 / 老板/经营者 / 财务 / 供应链 / 合规
* **阶段**：找机会 → 找对象 → 判断 → 决策 → 执行 → 跟进 → 风控 → 复盘 → 监控
* **市场**：内贸 / 外贸 / 全球
* **频率**：每日高频 / 每周 / 事件驱动 / 低频高价值
* **AI 价值**：查询 / 聚合 / 判断 / 计算 / 推荐 / 执行 / 监控
* **技术形态**：Workflow / Skill / Agent / 组合（仅标签）

### 0.4 来源标记约定

* `[会议明确]` 已基本拍板
* `[会议强倾向]` 倾向强但未完全定稿
* `[本次新增建议]` 会议未充分讨论、基于真实化工作业链补充
* `[待验证]` 需客户或专家验证

### 0.5 技术形态总原则

* Workflow 优先 → Skill 第二 → Agent 最后 `[会议明确]`
* 禁止「一个场景一个 Agent」
* 数据调用：内部结构化 → 外部 API/MCP → Search → 明确缺失
* 不编造：实时库存、真实成交价、海外私域联系人、准确完整产能

### 0.6 全景树速览（L1→L4 目录）

* **1 内贸交易与经营**
  * 1.1 销售增长 → 智能潜客与商机 / 关键联系人与首触达 / 客户组合与复购预警
  * 1.2 采购与找货 → 需求结构化 / 图片物料识别 / 智能寻源与排序 / 到厂成本区域方案 / 询价分发与回价比较
  * 1.3 报价与交易辅助 → 询盘响应与销售报价 / 合同订单核对
  * 1.4 物流与履约 → 运费运输与交期方案 / 质量异议与交付异常
  * 1.5 交易风控与信用 → 企业尽调 / 账期额度 / 供方资质与假货筛查
  * 1.6 价格经营 → 现货价格解释与区域价差
* **2 外贸交易与经营**
  * 2.1 市场进入与客户开发 → 海外市场与买家 / 海外联系人与合规触达
  * 2.2 全球采购 → 海外寻源与供应商筛选
  * 2.3 询盘与报价 → 询盘结构化、出口报价与跟进
  * 2.4 归类单证申报 → HS、申报要素与单证一致性
  * 2.5 国际物流与危险品 → Incoterms 总成本、路线与危运方案
  * 2.6 产品与交易合规 → SDS 审校本地化 / 制裁出口管制与付款初筛
  * 2.7 海外信用与收款 → 买方信用、付款与国家风险
* **3 产业研究与决策支持**
  * 3.1 品种与供需 → 产品速研 / 供需产能项目跟踪
  * 3.2 成本利润与产业链 → 成本利润传导 / 产业链替代与路线
  * 3.3 企业与竞争 → 企业研究与竞争格局
  * 3.4 政策技术项目 → 外部变化影响评估
  * 3.5 定期简报 → 品种日周月报与决策一页纸
* **4 期现与风险管理**
  * 4.1 期现价差 → 现货—期货—基差联合解读 / 月差区域跨品种价差与产业利润
  * 4.2 套保锁价 → 敞口与方案比较 / 套保效果与损益归因
  * 4.3 风险监控 → 压力测试、异常解释与分级预警

### 0.7 L4 保留门槛与展开规则

* 一个条目只有同时满足以下条件，才作为正式 L4 场景卡保留：
  * 能说清「谁在什么时刻为什么打开 ChemClaw」
  * 有独立、可验收的 Job To Be Done，而不是数据源、按钮、计算步骤或报告章节
  * 能从搜索升级到筛选、验证、计算、判断、排序、推荐、执行或监控中的至少一项
  * 数据缺失时仍有诚实的降级结果，不依赖模型编造库存、成交价、产能或联系人
  * 与相邻场景的输入、决策责任或最终制品至少有一项显著不同
* 正式保留的 L4 使用统一 16 项场景合同，并逐项给出 A–K Prompt 设计角度。
* 仅用于路线图占位、尚未通过价值/数据门槛的条目，必须标为 `[待验证]`，不能在场景中心提前展示。
* L5 原子步骤进入共享 Workflow / Skill / Tool 层，不为了增加卡片数量而独立成场景。

### 0.8 统一场景合同与 Prompt 合同

* **每个正式 L4 的 16 项场景合同**：场景定位、目标用户、触发时机、2–5 条用户原话、JTBD、最少输入、可选输入、专业框架、AI 主动条件、四级追问策略、完整流程、最终输出、可解释性、五类数据、真实性风险、技术形态。
* **每个正式 L4 的 A–K Prompt 合同**：角色、目标、专业维度、Prompt/Workflow/Skill/Agent 决策分工、信息不足、工具顺序、证据可信度、结果结构、专业判断、风险边界、5–10 行 Skeleton。
* “专业人员思考框架”只定义应检查的维度、规则与证据，不要求模型向用户暴露隐藏推理过程；对外只呈现结论、依据、计算、冲突和不确定性。
* 所有外部写入、触达、授信、订舱、申报、发布、交易和资金动作都属于**需授权执行**，不得由 Prompt 文字绕过权限/审批。

## 1. 内贸交易与经营

> P0 基本盘；以国内获客、采购、报价、履约、信用和价格经营为主。正式 L4 仅保留以下 16 个，来源标签不代表当前已实现。

### 1.1 销售增长

#### 1.1.1 新客开发与首触达

##### 1.1.1.1 智能潜客与商机发现 `[P0]` `[会议明确]` `[会议强倾向]`

###### 场景合同（1–16）

1. **场景定位**：把企业发现、ICP 匹配和“为什么现在值得联系”的招标、扩产、项目建设等信号合成一个潜客优先级场景；招投标是信号，不另立重复场景。
2. **目标用户**：内贸销售、销售经理、市场拓展与老板。
3. **触发时机**：开拓新品/新区、线索池不足、发现招标或扩产事件、需要安排本周拜访名单时。
4. **用户原始问题示例**：“帮我找华东可能采购聚醚多元醇的客户，优先最近有扩产动作的”；“哪些企业最近有环氧树脂招标，值得我们本周联系”；“把这批企业按匹配度和证据可信度排出前二十名”。
5. **JTBD**：在有限时间内得到一组可核验、可排序、可解释的目标账户，并知道此刻联系它们的理由。
6. **最少必要输入**：产品/SKU 或应用方向、目标地区、目标客户角色、明确排除项。
7. **可选输入**：理想客户画像、销售半径、历史成交样本、产能/规模偏好、时间窗、线索预算。
8. **专业人员思考框架**：先做产品—应用—采购角色映射，再做主体归一和集团/工厂拆分；区分适配度与证据置信度；以信号新鲜度、采购可能性、区域可服务性和冲突证据排序。
9. **AI 主动想到**：识别贸易商/货代噪声、同集团重复主体、招标代理人与最终使用方差异、信号过期、已有客户和竞品锁定关系，并提示转入关键联系人场景。
10. **追问（必须/最好/假设/画像）**：必须：产品或地区存在歧义时澄清；最好：确认客户类型和排除项；可假设：采用常规企业规模和最近 12 个月信号窗并标注；画像复用：历史 ICP、排除名单和销售区域。
11. **完整流程**：需求归一 → 内部企业/产业链召回 → 招标/扩产等信号合并 → 主体去重 → 多源核验 → 适配度与置信度双评分 → 排序分桶 → 生成下一步。
12. **最终输出**：潜客优先清单、每家推荐原因、关键信号与日期、证据链接、双评分、冲突/缺口、建议动作。
13. **可解释性**：逐项展示评分因子、证据来源与时间、排除原因；不得用单一招标或搜索摘要直接宣称真实采购。
14. **所需数据（内部/API/Search/私有/缺失五类）**：内部：企业库、产业链/应用关系、已核实商务数据、历史客户与价格覆盖；API：工商/登记、招投标、项目与企业事件接口；Search：企业官网、公告、新闻和园区公开信息的补证；私有：CRM、赢丢单、销售区域、黑白名单与人工核实记录；缺失：真实采购量、当前采购负责人、未公开项目与线下关系。
15. **数据缺口真实性风险**：联系人和采购意图可能过期；主体混同、信号误读和单源偏差会制造假商机，必须显式标示未知与冲突。

```text
你是产业风险监控助手，先验证数据再解释市场。
读取授权敞口、指标、阈值、情景、责任人和静默规则。
做单因子/联合压力，计算价格、基差、保证金和现金影响。
异常先排坏点、换月、单位和节假日，再查事件证据。
按信息/关注/行动/紧急分级，去重并绑定处置 SOP。
输出触发项、影响、原因、动作、责任人和期限。
压力不是预测；交易和资金动作永不自动执行。
```

> 由 37 个正式 L4 反推；能力是跨场景复用的深模块，不是用户场景。默认复用顺序为 Workflow → Skill → Agent，不创建“一卡一 Agent”。

### 5.1 共享能力分层

#### 5.1.1 化工对象与领域语义

* 产品身份归一：中文名/英文名/俗名/CAS/分子式/混合物/商业牌号/规格/等级。
* 产品—用途—行业—采购角色映射：服务潜客、寻源、报价和研究。
* 危险属性、包装、储运与法规身份：服务采购、合同、物流、SDS 和申报。
* 产业链节点、关系与版本：服务潜客匹配、成本传导、替代与研究；标准产业链图必须可审阅、可版本化。

#### 5.1.2 主体、关系与证据

* 企业主体、集团、工厂/站点、品牌和收付款主体归一。
* 企业角色识别：生产商、经销商、终端、货代/报关行、招标代理、通知方。
* 联系人—岗位—主体—时间核验与隐私边界。
* 证据台账：来源、时间、主体、口径、适用范围、冲突、置信度和人工核实状态。

#### 5.1.3 交易计算与文档

* 数量、单位、币种、含税/未税、地区和时间统一。
* 运费、到厂/到岸成本、毛利、现金周期、敞口、基差、价差和压力情景的可审计计算。
* 询价/报价、合同、发票、箱单、SDS、信用证等结构化抽取与一致性检查。
* 图表、清单、一页纸、报告和版本差异的统一交付。

#### 5.1.4 规则、权限与运行时

* 场景路由、最小追问、显式默认、NeedsReview 和诚实降级。
* 现货/国内期货/国际原油等市场口径路由；禁止错误来源交叉替代。
* 外部触达、CRM/ERP 写入、授信、订舱、申报、文件发布、交易和资金动作的权限/审批门禁。
* 定时/事件触发、变化检测、静默规则、通知失败重试、审计和恢复。
* Prompt/Skill/Workflow 版本、评测样例、回退和热更新；安装或修改后后续调用使用最新有效版本。

| 共享能力 | 主要消费场景 | 适合固化为 | 不应承担 |
| --- | --- | --- | --- |

### 5.3 Prompt、Workflow、Skill、Agent 的责任界面

* **Prompt**：理解用户语境、组织专业表达、解释取舍；不保存权威事实、不承担关键算术、不授权外部动作。
* **Workflow**：可重复的取数、校验、计算、路由、审批、文档组装、审计和恢复；默认首选。
* **Skill**：可版本化的化工专业规则、术语、模板、验证和兼容性；不能只复制一份说明文本。
* **Agent**：仅用于跨源冲突、开放式研究、多跳影响或复杂谈判语境；必须继承相同权限、市场口径和证据规则。

### 5.4 L5 原子任务目录

> 各 L4 场景合同的第 11 项“完整流程”就是该场景的 L5 顺序；以下原子任务跨场景复用，不在场景中心单独占卡。

* **识别与归一**：产品/CAS/牌号/规格消歧、主体/集团/站点去重、单位/币种/税价/时间统一。
* **召回与过滤**：企业/供方/买家候选召回、货代/代理/通知方过滤、历史客户/黑名单排除。
* **核验与取证**：官网/登记/公告/单证交叉、联系人时效、证照/授权/项目状态、来源时间和冲突记录。
* **计算与比较**：适配/置信度分离、到厂/到岸成本、毛利/现金周期、基差/价差/敞口/压力情景。
* **规则检查**：危化身份、合同/单证一致性、HS 候选、SDS 跨章、名单命中消歧、权限和审批。
* **生成与交付**：采购 Brief、清单、询报价草稿、差异表、图表、报告/一页纸、待办与责任人。
* **执行与反馈**：人工确认、外发/写入/订舱/申报/交易审批、结果回收、失效反馈、评测与版本回退。

### 6.2 当前长板与优先做深 `[会议明确]`

* 企业与已核实商务数据 → 内外贸潜客、供方、尽调。
* 现货价格与国内行情路由 → 价格经营、研究、期现。
* 产业链与化工百科 → 产品归一、应用匹配、成本传导和研究。
* 上述“长板”只代表相对优势，不等于品种/地区/年份完整覆盖；每次调用仍需返回覆盖和更新时间。

### 6.3 按闭环采购外部数据

1. **第一优先**：联系人可核实来源与失效反馈——决定拓客能否从名单走到真实行动 `[会议明确]` `[待验证]`。
2. **第二优先**：稳定招投标/项目事件——增强“为什么现在联系”，但不独立采购成孤岛。
3. **第三优先**：海关/提单试点——先验证重点品种/国家覆盖、货代过滤和客户使用率，再扩大合同。
4. **第四优先**：真实运价/路线——仅在到厂/到岸成本闭环有用户后加深。
5. **第五优先**：产能、装置、园区——为研究纵深采购，不应抢占内贸交易首包预算。

### 6.5 外部规范锚点（用于规则库选型，不替代专业意见）

* 商品归类以 [WCO Harmonized System](https://www.wcoomd.org/en/topics/nomenclature/overview/what-is-the-harmonized-system.aspx?p=1) 和各法域现行税则为基础；中国企业可参考海关的 [商品归类预裁定办事指南](https://online.customs.gov.cn/static/pages/guides/000729004001/000729004001.html)。
* 贸易条款以 ICC 的 [Incoterms® 2020](https://iccwbo.org/business-solutions/incoterms-rules/incoterms-2020/) 为当前锚点；产品实现必须保存版本，不把三字母术语简化为运费模板。
* 海运危险品以 IMO 的 [IMDG Code](https://www.imo.org/en/publications/pages/imdg%20code.aspx) 及承运人当前政策为锚点；空运另查 [IATA Dangerous Goods Regulations](https://www.iata.org/en/publications/dgr)。
* SDS/GHS 结构以 UNECE 的 [Globally Harmonized System of Classification and Labelling of Chemicals](https://unece.org/about-ghs) 及目的国实施法规为锚点。
* 制裁/出口管制筛查至少需要当前官方源，如 [OFAC Sanctions List Search](https://ofac.treasury.gov/sanctions-list-search-tool) 与美国 BIS 的 [Consolidated Screening List](https://www.bis.gov/node/18530)；“无命中”不等于法律放行。

## 8. 分类完整性自检

### 8.1 内贸链路是否完整

* 已覆盖销售增长、采购找货、报价订单、物流履约、交易风控信用和价格经营；复盘类需求并入客户组合/定期视图，未为了“齐全”增加弱卡片。

### 8.2 外贸链路是否完整

* 已覆盖市场进入、客户触达、全球采购、询盘报价、HS/单证、国际物流危化、SDS/贸易限制以及信用收款；汇率、关税、运费是计算能力而非独立场景。

### 8.3 研究分析是否完整

* 已覆盖产品、供需产能项目、成本利润、产业链替代、企业竞争、政策技术项目与定期决策制品；投资判断只给证据/情景，不包装荐股。

### 8.4 期现与风险是否完整

* 已覆盖期现基差、月差/区域/跨品种价差、产业利润、敞口与锁价、效果归因、压力/异常/预警；明确不自动交易、不承诺收益。

### 8.5 是否存在重复场景

* 招投标/扩产并入潜客商机信号；海关数据并入海外买家；询盘结构化/报价/跟进合为转化闭环；运费/Incoterms 是方案内能力。企业尽调与供方验真保留，是因决策责任和最终制品不同。

### 8.6 颗粒度是否一致

* 37 个正式 L4 都对应一个用户可独立发起、可验收的 JTBD；L3 只做任务簇；单位换算、主体去重、运费计算、名单查询等留在 L5/共享能力。

### 8.7 是否误把数据当场景

* 企业库、价格库、招投标、海关、搜索、名单、图谱都只出现在数据/能力层；用户入口以“发现、比较、核验、决策、准备、监控”命名。

### 8.8 是否误把技术形态当场景

* Workflow/Skill/Agent 仅用于每个 L4 的实现建议；没有“Google Agent”“海关 Agent”“一个场景一个 Agent”。

### 8.9 是否满足 Prompt 完整性

* 37 个正式 L4 均有 16 项场景合同、A–K Prompt 合同和 5–10 行 Skeleton；专业框架定义检查维度，不要求泄露模型隐藏推理。

### 8.10 仍需业务验证的争议

* 联系人来源、更新频率、隐私与可联系率；海关数据重点品种/国家覆盖及货代过滤；运费/毛利默认阈值；质量异议和海外信用是否值得独立入口；产能台账维护成本；期现用户规模；套保治理责任；1.0 八场景卡片对个人用户的导航理解度，均保留 `[待验证]`。

# ChemClaw 1.0 场景建议

> 组合原则：内贸交易闭环优先，保留一个外贸验证位；八场景必须用真实数据/真实任务演示。分数是验证起点，不是“已批准开发”。下列定量成功阈值均为 `[本次新增建议]` `[待验证]`，不是会议拍板或既有基线。

## 1.0 推荐组合（8 个正式 L4）

### A. 智能潜客与商机发现 `1.1.1.1` `[会议明确]` `[会议强倾向]`

* **为什么现在做**：内贸基本盘，把企业和产业链长板转成“为什么这家公司值得现在联系”。
* **谁会用**：内贸销售、销售经理、老板。
* **核心价值**：可核验、可排序、可解释的账户清单，而非黄页。
* **最小 Demo**：产品+区域+客户类型 → Top 20；合并招标/扩产两类信号；展示适配度、置信度、来源、排除理由。
* **暂时不做**：全网全能雷达、保证采购意向、自动触达。
* **成功标准**：5 名目标销售各完成 3 次真实任务；人工核验 Top 20 中“值得进一步核实”比例 ≥60%；至少 3 条进入真实跟进。
* **下一阶段**：接关键联系人、CRM 去重和信号订阅。

### B. 关键联系人与首触达准备 `1.1.1.2` `[会议明确]`

* **为什么现在做**：会议认定的闭环破局点；只有公司名不能推进销售。
* **谁会用**：销售、BD、销售主管。
* **核心价值**：岗位路径+可信证据+首触达准备，并在无个人信息时诚实降级。
* **最小 Demo**：对 10 个确认账户给已核实/可能/岗位路径、来源日期、置信度和首触达要点。
* **暂时不做**：购买/推测私人手机号、自动加微或群发。
* **成功标准**：人工抽检事实准确率 ≥90%；过期/错配可反馈；至少 30% 账户形成可执行岗位路径；零未经审批外发。
* **下一阶段**：批量补全、渠道偏好和跟进节奏。

### C. 采购需求结构化 `1.2.1.1` `[会议明确]`

* **为什么现在做**：是寻源、比价和询价的统一低风险入口，可显著减少无效追问。
* **谁会用**：采购、贸易商、生产计划和老板。
* **核心价值**：把模糊品名/用途转成有硬约束、偏好、未知和替代边界的采购 Brief。
* **最小 Demo**：自然语言/图片附言 → 最小追问 → 结构化需求卡 → 用户确认 → 转寻源。
* **暂时不做**：从相似品自动推定规格/安全身份。
* **成功标准**：关键身份错误为零；平均追问不超过 3 个；80% 样例可直接进入供应商检索/询价。
* **下一阶段**：接图片物料识别和用户常购画像。

### D. 智能寻源与供应商排序 `1.2.2.1` `[会议明确]`

* **为什么现在做**：采购基本盘，最能展示 ChemClaw 的产品、企业、价格和风险联合判断。
* **谁会用**：采购、贸易开单、老板。
* **核心价值**：A/B/C 方案与供方排序，不把最低挂牌价当最佳方案。
* **最小 Demo**：确认采购 Brief → 候选供方 → 主体/角色核验 → 适配/价格参考/履约/风险多目标排序。
* **暂时不做**：保证实时库存/成交、自动询价或下单。
* **成功标准**：采购专家对 Top 5 的“值得询价”认可率 ≥70%；每个候选可解释；未知值不参与伪精确排序。
* **下一阶段**：接询价分发、回价比较和供方准入。

### E. 到厂成本与区域方案比较 `1.2.2.2` `[会议明确]`

* **为什么现在做**：把报价、运费和风险转成可审计的决策，Demo 结果清晰。
* **谁会用**：采购、贸易商、供应链和经营者。
* **核心价值**：统一规格/税价/单位后比较总成本、交期与风险。
* **最小 Demo**：三地报价+数量+目的地 → 运费/装卸/资金/损耗拆解 → 基准/上行/下行情景 → 推荐方案。
* **暂时不做**：把估算运价当有效报价、承诺毛利。
* **成功标准**：计算样例 100% 可复算；单位/税价错配被拦截；用户能说明推荐方案的至少两个取舍因素。
* **下一阶段**：接真实承运询价和销售报价共用计算层。

### F. 交易对手企业尽调 `1.5.1.1` `[会议强倾向]`

* **为什么现在做**：高痛点、高专业壁垒，可把多平台两天工作压缩为可复核底稿。
* **谁会用**：老板、风控、财务、采购/销售负责人。
* **核心价值**：跨经营/财务/司法/履约关联，且同时寻找反证与补查动作。
* **最小 Demo**：一个真实主体 → 时间线/关系 → 事实/推断/未知 → 风险分级 → 合作条件和补查清单。
* **暂时不做**：法律定性、自动拒绝或自动授信。
* **成功标准**：100% 关键结论可回到证据；专家认为至少节省 50% 查数时间；无诽谤性确定结论。
* **下一阶段**：批量初筛、账期额度和持续事件复审。

### G. 现货价格解释与区域价差 `1.6.1.1` `[本次新增建议]`

* **为什么现在做**：高频日活入口，能直接复用现货数据并服务采购/销售。
* **谁会用**：销售、采购、贸易商和老板。
* **核心价值**：给“价+口径+因+经营含义”，不是单一报价或伪预测。
* **最小 Demo**：品种/地区 → 最新价/时间/来源 → 趋势/区域差 → 驱动事实/推断 → 扣运费后的经营含义。
* **暂时不做**：保证走势、期货冒充现货、网页挂牌冒充成交。
* **成功标准**：口径字段 100% 显示；有数据品种首屏短答稳定；目标用户一周内重复使用 ≥2 次。
* **下一阶段**：区域提醒、客户报价联动和期现联合解读试点。

### H. 海外市场进入与买家发现 `2.1.1.1` `[会议明确]` `[会议强倾向]`

* **为什么现在做**：保留外贸必做验证位，尽早判断海关/贸易数据是否能形成付费差异。
* **谁会用**：外贸业务、出口经理和老板。
* **核心价值**：市场选择+去货代买家证据，不是海外 Google 公司列表。
* **最小 Demo**：一个品种+两个国家 → 国家短表 → 买家清单 → 交易连续性/角色/置信度 → 排除项。
* **暂时不做**：覆盖全球所有品种、私域联系人、自动开发信群发。
* **成功标准**：选 2 个重点品种×2 个国家，人工核验角色准确率 ≥80%；外贸用户愿导入自有海关表继续使用。
* **下一阶段**：联系人与触达、询盘报价转化；不达标则暂缓商业海关数据扩大采购。

## 1.0 不进首包

* 客户组合自动预警、合同/质量异常、账期额度、海外信用、深度产能台账、政策技术专题和全套合规工作台：价值存在，但需更多私有数据、专家责任或持续维护。
* 期现联合解读仅作为定向专业试点；套保、效果归因和压力监控不进首包，直到头寸对账、治理和审批闭环通过。
* 自动投机、自动授信/发货/申报/发布、保证实时库存/全市场成交/完整产能、SEO/独立站、电商平台运营和重 ERP 集成明确不做。

## 1.0 产品形态与验收节奏

* 独立 ChemClaw 场景中心为主，企微/个人微信等作为连接器；卡片进入后仍允许自然对话 `[会议强倾向]`。
* 每个 Demo 使用真实任务、真实证据和可追溯计算；先测“用户是否愿意拿它工作”，再扩数据和自动化。
* 两周一轮：5–8 位个人工作者任务测试 → 失败样例归因（数据/规则/交互/价值）→ Prompt/Workflow/Skill 分层修订 → 版本化回归。
* 任何“成功率”必须说明样本、品种、地区、时间和判定人，避免用演示样例替代产品验证。

## 附录 B. 从总纲到实现的工作顺序
