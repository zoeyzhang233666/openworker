# 回答模式、研究收敛与可视化交付：诊断及候选设计

日期：2026-09-29。状态：**用户已于本轮明确要求“开始做吧”，按下述计划分项实施**。真实模型账号调用、发布和安装仍遵守既有门禁。

本轮独立验收范围：第 1 项的后端分段计时与固定评测题库。复用 TurnTrace，增加每次模型请求准备、HTTP 请求/响应头（先覆盖 OpenAI 兼容链路）、原始 content/思考首段、Provider 输出正文首段及引擎正文首段时间；记录工具阶段墙钟时间、压缩时间及缓存用量。只保存数值/枚举，不采集正文/URL/凭据。重试逐次计时，停止冻结结果，旧 trace 可读，未观测项保持空值。屏幕绘制、入口 MCP 等待、首个有用结论及质量由评测记录明确另列，不能用后端时标代替。真实账号基线未授权时只完成离线注入验证，不宣称首段目标已达标。

## 2. 这是哪些经典问题的变体

1. **过度工具调用 / ReAct 循环不收敛**：每步看似合理，整体缺少“再查一次能解决哪个缺口”的停止条件。属于有成本的信息获取与最优停止问题。
2. **上下文膨胀与低信噪比检索**：增加网页不等于增加证据；重复摘要与操作历史占据上下文，后续每轮又支付这些输入成本。
3. **输出验收不足引发修复循环**：执行命令成功、磁盘存在文件、产物可发现、预览可打开是四个不同状态。只拿到前一个状态，模型只能猜测后续失败原因。
4. **把确定性渲染当成开放式编程任务**：普通业务图表每次临时写 Python，承担字体、路径、依赖、样式等随机失败；适合交给稳定渲染实现。
5. **同一执行策略承担不同服务等级**：常识问答、轻量核验和深度研究共享长任务策略，缺少显式速度/深度选择。

时间应拆为：入口准备 + 每次模型等待/生成 + 工具关键路径 + 交付验证。并行只能缩短工具关键路径，通常不会自动节省 token；更多子智能体也不保证更好结论。

## 3. 产品合同（候选）

两个独立维度：**研究深度：快速 / 深度探索**；**交付：聊天 / 可视化报告**。研究模式与 PermissionEngine 的审批模式分离，不能复用现有权限 mode 字段。界面只有真实闭环后才显示新控件。

快速作为普通问题默认：

- 基于已有资料足以回答时直接流式回答，不为了仪式感调用搜索或生成文件。
- 需要当前事实时仍可联网；保留基础 web 和按需工具发现，不按公司名/品种关键词禁工具，不强制委派。
- 默认一批独立搜索/读取；建议初始预算 2 个搜索查询、3 个页面读取，只有明确缺口再允许一轮补查。数值是待评测参数，不是已上线门槛，也不是所有任务通用真理。
- 接近预算时先交付有依据的答案，明确缺口；用户要求完整研究且尚未满足时标“部分完成”，提供真实的继续入口，不把短答标成完整成功。
- 常识问答首段目标 1–2 秒；普通联网概览有用结论目标 10–30 秒。均是待验收目标；当前 7–12 秒首段的模型链路尚不满足，不能承诺秒出完整研究。
- “收到/正在搜索”只算响应反馈，不算首个有用答案。对尚未核验的当前业务/财务事实不提前编结论。

深度探索：

- 先确定交付所需问题和证据，不默认加一轮澄清；普通明确请求可直接开始。
- 维护证据缺口、来源、发布日期/所属期间、互相矛盾的事实与停止原因。
- 只为尚未解决的重要问题扩展；独立只读研究可在既有五路上限内并发，默认实际并发更小且共享预算，不强制多代理。
- 分段交付已核验发现，允许停止；总结、引用核对和产物验证预留预算。继续/恢复复用已收集证据。
- 保留现有共享预算与权限，只增加明确选择的执行目标，不重建第二套引擎。

模型思考强度是第三个底层参数：快速模式可使用已验证支持的低推理配置，深度模式可提高；隐藏思考文字不能加快服务端推理。模型自动切换须有用户可见策略，不覆盖现有会话模型选择。

## 4. 搜索收敛与答案质量

在现有执行链路增加轻量任务证据状态，不每轮再调用昂贵的“裁判模型”：

- 每个检索动作关联一个待解问题；记录规范化 URL、内容摘要/hash、事实/引用位置、日期、相关性、失败原因。
- 任务内复用相同 URL 和等价只读查询；跨任务缓存必须考虑 TTL、参数、权限/身份、数据新鲜度及用户强制刷新。不能把昨天价格当今天结果。
- 正文提取先去导航/重复文本，按问题截取相关段落；保留原文定位，避免把全文粗暴截断或多次摘要造成数字失真。PDF/财报用能保留页码与表格的读取路径。
- 关键问题已有足够直接证据、连续两次新增证据近乎为零、预算/时限到达时进入综合；“两次无增益”是启发式，要允许真实矛盾和新事实触发补查。
- 同一产物重复报错应按产物与错误类型聚合；两次自动修复仍无进展则保留正文、说明失败并降级，避免 shell 命令变体无限尝试。
- 失败重试必须改变一个有依据的因素，记录上次失败和新尝试差异；不能盲目改为 ASCII 文件名。

卓创案例建议完成合同：主营业务、产品/服务、客户和收费方式、业务之间的关系、已披露结构与增长方向；区分公司披露和分析推断。优先公司官网和最新可用定期报告，对关键矛盾再交叉核验，不为达到来源数量凑网页。未披露收入拆分时不画伪精确占比图。快速版重点形成业务矩阵与结论；深度版再展开财务期间、竞争及风险。

## 5. HTML 与图表交付

建议普通聊天继续直接回答；用户要业务梳理/研究报告时可默认精装 HTML（审批后取代旧 MD 主阅读面决定）。MD 仍可作为内容源、导出和降级格式。不能仅把 system prompt 改成“每次写漂亮 HTML”。

采用深模块：模型通过一个小 Interface 提交内容块、引用、ChartSpec 和样式主题，模块负责验证、渲染、文件存储、产物注册及状态返回。隐藏字体、路径、扩展名和搬文件规则。首版先包装现有 `cook_report_html`，让既有 MD + ChartSpec 通过固定主题生成 HTML，避免要求模型额外抄一份全文 JSON。需要复杂布局时再渐进增加受约束内容块。

交付结果至少含 artifact_id、工作区相对路径、MIME、存在/大小、静态校验与预览状态、可打开链接、结构化错误。`written` 不等于 `preview_verified`。相同内容版本重复调用应幂等；中文展示名与存储 ID 分离，中文路径仍须测试支持。

默认图形选择：业务关系用 HTML/SVG/带中文边标签的 Mermaid；数据图用现有 ChartSpec/Chart.js；无数据就用定性业务卡片，不编数值。只有用户要求图片文件、平台需要预览或静态导出时才导出 PNG/SVG，优先复用同一图规格。真正的插画/照片另属图像生成能力。

模板需要有限主题、排版/颜色/空白规则、移动端和打印支持、可追溯引用；不得出现无效按钮。复用既有 HTML 沙箱，可信渲染代码与外部数据分离；依赖失败须有表格/正文降级。普通交付不新启浏览器服务；开发验收单独做沙箱实际预览测试。不得让网页再运行第二套研究代理。

旧 D-077 后台自动做网页因失败率高被撤销。本方案的不同在于同源、受约束、可验证的渲染，不是重新启动另一个自由编程 Agent。默认交付变化必须经过用户审阅。

## 7. 验收方法

建立固定的约 12–20 条任务：问候、常识、公司业务概览、最新事实、财报 PDF、已给资料总结、行情趋势、显式不联网、深度研究、HTML 报告、明确 PNG 导出、来源失败。包含用户卓创案例及中文路径/切目录/恢复案例。

分两层比较：固定模型/提供商/推理参数/输入资料比较执行框架；固定执行策略比较模型与提供商。Claudian/WorkBuddy 只能在用户提供相同任务与可比配置/记录时纳入产品级盲评，不能声称完全同条件。

记录：HTTP 发出/响应头/上游首正文/引擎首事件/屏幕首正文/首个有用结论/完成；模型请求次数、工具次数、重复查询/URL、有效证据数、输入输出/缓存 tokens、压缩次数、产物成功率。报告中值、尾延迟及样本数，不能用两次结果称稳定 P95。

质量盲评：任务覆盖、事实正确、引用支持、分析洞见、未知项诚实性、阅读性；总时长下降但关键事实和引用变差不得过关。HTML 加分不能掩盖内容变差。无实际供应商/模型测试时不得宣称“秒回达标”。

初次诊断仅核对文档、源码与公开仓库；用户批准后的源码实施和实际回归记录在 [实施计划](../plans/2026-09-29-chemclaw-answer-modes-artifacts.md)，不把旧测试数当本次结果。
