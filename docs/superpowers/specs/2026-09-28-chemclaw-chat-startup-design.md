# 新对话被 MCP 初始化阻塞：修复规格

属于已批准加固计划的 MCP 连接隔离与对话回归，不改变工具权限或模型设置。

## 观察与边界

用户确认 deepseek-v4.1-flash、新对话、“你好”。当前开发页面持续显示处理中；服务的最新会话/追踪仍早于该消息，两个 MCP 均有 WinError 121 超时。源码在 WebSocket 接收消息前等待所有 MCP，连接管理器又持有跨服务器全局锁等待初始化，且退出路径可能不结算 ready。尚未证明本次故障已进入模型接口，不能归咎模型或密钥。

## 行为

- 所有会话共用的 MCP 准备入口只短暂等待快速连接（最多 250ms），其余在后台连接；会话可以接收、保存和处理普通消息。
- 各服务器独立连接，同服务器共享一个连接尝试；自动连接有 15 秒期限，取消/失败必须结束等待，不能拖住其他服务。
- 成功后补挂到所属会话，后续工具发现可见；连接期间撤销的授权、禁用或变更的配置不允许迟到挂载。
- 后台连接不执行模型或 MCP 业务工具，不擅自修改设置、凭据或联网限制。连接状态和错误继续从现有 MCP 页面查看。
- 退出或重载时清理连接准备任务；保留已有权限、审批、会话隔离。

## 验收

离线模拟永不就绪 MCP，普通聊天仍能完成；慢服务不拖住正常服务；多会话同服务只初始化一次；取消无悬空等待；迟到服务可发现，禁用后不挂载。实际 deepseek 请求兼容性仍需另行真实测试，不能把模拟通过称为线上修复已验证。
