# ChemClaw 报告网页版烹饪

**日期**：2026-08-06  
**状态**：已废止自动烹饪（D-077 修订；2026-08-07）  

**决策**：D-077（2026-08-07 修订；并修订 D-072 G4）  
**范围**：网页版改为可选、先对齐再对话内生成；拆除 turn 后自动后台烹饪。仍保留右侧 HTML 产物预览沙箱。不碰对话区内嵌大板 Artifact。

> **修订说明（2026-08-07）**：自动一锅出交互 HTML 实测失败率过高，不适合作为固定交付模块。下文「目标 / 产品行为」中的自动烹饪、短气泡、三态文案、设置默认开均已废止；以 [DECISIONS.md](../../chemclaw/DECISIONS.md) D-077 修订条款与 DOMAIN「交付与产物」为准。

## 背景

当前智能体习惯在 turn 内写入最终 `.md` 报告并用 `artifact:` 链接交付（见全局长程附录与产业链龙虾提示）。D-072 G4 曾要求默认 Markdown，并「白话问要不要更美观的网页」。实践中：

1. 用户希望交完 md 后自动有可交互网页版，但模型同轮写 HTML 太慢，会挡住阅读已生成的回答与文档版。
2. 对话气泡常与 MD 正文大量重复；用户希望主阅读面更接近 ChatGPT/Claude 的可交互精装页，而不是两份长文。
3. 产品共识（grilling，2026-08-06）：网页版为权威阅读面；文档版为底稿；后台模型烹饪开放 HTML/JS；短气泡；右侧预览；设置总开关默认开。

## 目标

1. **文档版交付后自动烹饪网页版**（设置开启时），主 turn 已结束即可读回答与 MD，烹饪不阻塞。
2. **有最终文档版时强制短气泡**（结论/要点 + 文档入口），消除「气泡 ≈ MD」重复。
3. **网页版在右侧产物预览打开**；同会话就绪时自动打开，并显示龙虾文案三态。
4. **可交互**：鼓励滑块、计算器、筛选等；定量只使用报告已有数与关系。
5. **预览安全底线**：**（D-078 修订）** 允许外链脚本与只读 GET；禁 POST 本地报告。深度研究仍走对话 MCP。

## 非目标（一期）

- 对话区中间/下方 Claude 式大板 Artifact（右侧预览即可）。
- 硬同源逐字校验（已改为网页版权威 + 定量不编造）。
- 用网页版 `fetch` 替代对话内 MCP/技能做深度研究。
- 外部系统默认浏览器打开本地 HTML 作为主路径。

## 产品行为

### 触发

- 当设置「md文档交付后生成网页版」开启（**默认开**），且某轮助手回复交付了最终 `.md` 报告时，在**该 turn 成功结束后**入队烹饪。
- 实现识别：回复中的 `[标题](artifact:相对路径.md)`（可多条，各烹一份）。用户可见文案**禁止**使用「芯片」一词。
- 设置关闭：不入队、不显示烹饪文案。
- 非最终草稿、无 `artifact:….md` 的普通 `.md` 写入：不触发。

### 设置项

| 语言 | 名称 | 说明 |
|------|------|------|
| zh-CN | md文档交付后生成网页版 | 交完 md 文档后，自动在后台做网页版。你可以先看回答和文档；网页版做好了会提示，并在右侧打开。 |
| en-US | Generate webpage after Markdown delivery | After a Markdown report is delivered, cook an interactive webpage in the background. You can keep reading the reply and the doc; when ready, you get a notice and it opens on the right. |

Prefs 缺省为开启；已有用户 prefs 若无该键则视为开。

### 短气泡

存在最终文档版交付时，助手最终气泡只保留：

- 几句结论或要点；
- 文档版入口（`artifact:….md` 链接，界面展示为可点的产物入口，文案称「文档」/「文档版」）。

不得再铺与文档版重复的长文。靠全局与智能体提示词约束（实施计划 Task 6）；不做把已生成长文强行折叠藏掉的 UI 硬截断作为主策略。

### 烹饪任务生命周期

1. **入队**：turn 结束 → 解析当轮最终 md 路径列表 → 对每一路径启动烹饪（或合并为每文件一任务）。
2. **取消**：同一相对路径若已有未完成烹饪，先取消再开新任务（以最新文档版为准）。
3. **进行中**：对话区显示进行中文案；用户可继续读短气泡与文档版，可继续发消息。
4. **成功**：写入网页版产物（与 md 配对的工作区 HTML；具体命名在实施中约定并测）→ 成功文案 → 若用户仍在该会话则右侧自动打开该 HTML。
5. **失败**：失败文案 + 「再下厨」重试入口；文档版始终可读；不阻塞对话。
6. **通道**：窄通道后台任务（无用户工具循环、不代发用户气泡），类似 Mermaid 就地修图的「另起模型调用」模式；使用当前会话可用模型/提供商。

### 网页版内容约定

- 开放 HTML/JS：可为精装排版、导航、折叠，以及滑块/计算器/筛选等小工具。
- **权威面是网页版**；叙事结构可相对文档版重排或加导读。
- **定量不编造**：控件公式与默认值只能使用文档版（烹饪输入）中已出现的数与关系；不得无中生有。
- 深度数据仍应来自此前对话研究；网页只读 GET 仅作展示/点缀，不充当第二研究代理。

### 预览安全

右侧 HTML 预览：

| 允许 | 禁止 |
|------|------|
| 页面内联脚本（自包含） | 外链 `<script src="https://…">` |
| 图片等静态资源 URL | 将本地报告内容 `POST`/`PUT` 出去 |
| 只读 HTTP `GET`（公开资料） | 任意写方法、凭证外传 |

沙箱策略在实施中落到 webview/iframe CSP 或等价拦截；失败时降级为可读错误，不崩主 UI。

### 打开与预览

- 主打开面：右侧产物预览（复用现有 RightRail 产物能力，延伸 HTML）。
- 就绪且用户仍在**该会话**：自动打开新网页版。
- 用户已离开该会话：不抢焦点；回到会话后可通过成功文案/产物入口打开。
- 仍禁止用 browser 工具验证 `file://` / localhost（D-075）；本地页靠应用内预览。

## 文案（中文定稿）

`{标题}` 为报告标题（来自链接文案或文件名展示名）。

| 状态 | 文案 |
|------|------|
| 进行中 | 龙虾下厨中，正在烹饪网页版《{标题}》，文档版可以先看~ |
| 成功 | 龙虾为你精心烹饪了网页版《{标题}》，比干巴巴的文字顺眼多了，点开看看吧~ |
| 失败 | 这锅网页版炖糊了，先看 md 文档版吧，要不要让龙虾再下厨一回？ |

英文界面提供对等翻译（实施时写入 `interfaceMessages`）；语气保持轻量，不出现「芯片」。

## 验收标准

1. 设置默认开；关闭后交 md 不出现烹饪进行中/成功/失败文案，不生成网页版。
2. 开启时：turn 结束后出现进行中文案；此前即可打开文档版预览阅读。
3. 烹饪进行中，用户可继续滚动对话、读 MD、发送新消息；主 turn 不因烹饪保持 `running`。
4. 成功：同会话右侧自动打开网页版；成功文案出现；产物列表可见 HTML。
5. 失败：失败文案 + 可重试；文档版仍可预览；对话不阻塞。
6. 同一 md 在后续 turn 再次作为最终交付出现时，取消旧烹饪并重烹。
7. 有最终 md 交付的回复，气泡为短答（人工或测例抽检提示词/样例会话）。
8. 预览：外链脚本与 POST 本地报告被拒绝或无效；只读 GET / 静态资源按策略可用。
9. 用户可见中文不出现「芯片」；设置文案与三态文案与上表一致。
10. 英文界面开关与说明可用。
